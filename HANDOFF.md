This is the orientation doc for anyone (a new AI chat, or Josh, or another
developer) picking this project up cold. Read this file top to bottom and you'll
understand what the project is, how it fits together, and how to safely make and
ship a change. Deeper detail lives in the `docs/` folder, linked throughout.

---

## 1. What this project is (in one paragraph)

It's a personal **NRL footy-tipping web app**. Each round it suggests who to tip,
with one hard rule: **the Sydney Roosters (short code `SYD`) are ALWAYS tipped in
their own game**, regardless of what the model thinks. It's a single self-contained
HTML page backed by a few small JavaScript data files. The data (ladder, draw,
odds, injuries, player ratings) is scraped and rebuilt automatically by a
GitHub Actions job every 4 hours, so it stays current **even when Josh's Mac is off**.
The site is hosted free on GitHub Pages.

- **Live site:** https://s1l3ncy.github.io/nrl-tipping/
- **GitHub repo:** https://github.com/s1l3ncy/nrl-tipping (public — required for free Actions + Pages)
- **Owner:** Josh (GitHub username `s1l3ncy`). Roosters supporter. "Roosters till we die."
- **Season context:** built during the **2026** NRL season.

## 2. The mental model (how it all connects)

```
   PUBLIC SOURCES                 GITHUB ACTIONS (runs every 4h, Mac off)      
   Zero Tackle (ladder,           ┌─────────────────────────────────────────────┐
   fixtures, injuries,            │ 1. cloud_fetch.py   scrape → *_dump.html/txt │
   player ratings)                │                     + rewrite nrl_players.js │
   nrl.com (draw meta)   ───────► │ 2. parse_nrl.py     dumps → nrl_data.js      │
   The Odds API (odds)            │ 3. learn_model.py   results → nrl_learned.js │
                                  │ 4. freeze_tips.mjs  → nrl_tiplog.js          │
                                  │ 5. validate_*.py    gate: must pass          │
                                  │ 6. cp html → index.html ; git commit + push  │
                                  └─────────────────────────────────────────────┘
                                                     │
                                                     ▼
   BROWSER (phone/desktop)   ◄──────────  GitHub Pages serves index.html
   nrl-tipping-guide.html loads nrl_data.js + nrl_learned.js + nrl_players.js,
   computes each tip in-page, always locks the Roosters pick.
```

The single most important thing to understand: **the website is `index.html`,
which is a copy of `nrl-tipping-guide.html` made by the workflow.** Editing the
guide file does nothing to the live site until a workflow run copies it over.
See `docs/DEPLOY_AND_OPS.md`.

## 5. How to make a change (the short version)

1. **Edit locally** in this folder (e.g. change model logic in `nrl-tipping-guide.html`, or a scraper in `cloud_fetch.py`).
2. **Test locally** where possible: open the HTML in a browser; run the Python scripts / validators. **Try the live scrape too** — this note used to say the editing sandbox has no network, but on 2026-07-29 a full live run of `cloud_fetch.py` completed from it. Test it rather than assuming; that assumption is why nobody noticed odds had never worked.
3. **Upload the changed file(s) to GitHub** (drag-drop in the repo's web UI, or drive it in the browser).
4. **Run the workflow**: repo → Actions → "Update NRL tips" → Run workflow. This rebuilds the data, copies the HTML to `index.html`, and publishes.
5. **Verify** via the raw file URLs (with a `?v=N` cache-buster) and the live site. See `docs/DEPLOY_AND_OPS.md`.

**Golden rules**
- The Roosters (`SYD`) are always tipped. Never "fix" that — it's the whole point.
- Never hand-edit `index.html`, `nrl_data.js`, `nrl_learned.js`, or `nrl_players.js` — they're regenerated and your edit will be overwritten.
- Time-sensitive fields (odds/news) are best-effort and may be `null`. That's normal, not a bug. (Weather was removed entirely on 2026-08-04.)
- Keep the HTML dependency-free (no CDNs) — it must work offline, opened as a local file.
